# 설치기 GUI 디자인 브리프

이 문서는 **GUI를 디자인하는 다른 세션이 이것만 읽고 시작할 수 있게** 쓴 인계 문서다. 구조·기술 결정은 재설계 문서가 소유하고, 여기는 **화면·상태·문구·시각 규칙**만 소유한다.

## 1. 한 줄 요약

`terra-setup --ui`가 loopback에 띄우는 **로컬 웹 앱**. 브라우저 탭 또는 앱 창으로 열린다. Windows·Linux가 같은 화면이다. 설치 · 업데이트 · 수정 · 복구 · 제거를 한 앱이 한다.

## 2. 사용자와 상황

| 누구 | 상황 | 설치기에 바라는 것 |
| --- | --- | --- |
| 처음 쓰는 사람 | 데스크톱에 Leaf를 깔고 기존 Tree에 붙인다 | 질문이 적고, 막히면 이유를 말해 준다 |
| 운영자 | 서버에 Tree + Leaf를 SSH로 깐다(헤드리스, 터널로 접속) | 한 번에 끝나고, 무엇을 건드렸는지 남는다 |
| 에어갭 환경 | 인터넷이 없다. 로컬 폴더/풀 번들로 깐다 | 원격 취득이 막혀도 설치가 죽지 않는다 |
| 이미 설치한 사람 | 업데이트·제거·옵션 변경 | 지금 상태가 먼저 보인다 |

## 3. 화면 흐름

```text
[시작] 감지: install-manifest.json
  ├─ 없음 ─► S1 역할 ─► S2 연결(Leaf) ─► S3 모듈 ─► S4 의존성 ─► S5 옵션 ─► S6 요약 ─► S7 진행 ─► S8 완료
  │                                                                                          └─ 실패 ─► E1 원인
  └─ 있음 ─► M0 유지관리 홈 ─┬─ 업데이트 ─► M1 변경점(코어·모듈 diff) ─► S6 ─► S7 ─► S8
                             ├─ 수정 ────► S5 옵션 + S3 모듈 범위 ─► S6 …
                             ├─ 복구 ────► M2 점검 결과(원장↔디스크) ─► S6 …
                             └─ 제거 ────► M3 보존/완전삭제 ─► M4 Tree 등록 해제 제안 ─► S6 …
```

- 위 화면 ID는 문서 안에서만 쓰는 지역 식별자다.
- 단계 표시줄(스텝퍼)은 설치 흐름에서만 보인다. 유지관리는 단계가 짧아 생략한다.
- 어느 화면에서든 "이전"이 된다. 단 S7(진행)부터는 취소만 있고, 취소는 롤백을 뜻한다.

## 4. 화면별 명세

### 4.1 설치기와 메인 GUI의 경계

설치기(`terra-setup`)와 메인 GUI(maingui의 시작 화면·설정)는 **서로의 일을 하지 않는다.** 정본은 maingui `docs/design/onboarding-gap-analysis.md`(§1, §5 결정)다.

| 때 | 맡는 곳 | 예 |
| --- | --- | --- |
| 설치 **때**의 선택 | **설치기** | 역할, 등록 방식(`account`·`token`·`auto`·`none`), WireGuard, 장치 이름, 옵션 |
| 설치가 **끝난 뒤** "이 기계가 지금 어떤 상태인가" | **메인 GUI** | 시작 화면(새 Tree / 기존 Tree에 붙기 / 나중에), 등록 코드 폼, 등록 상태 카드, 최초 관리자 마무리, 사용자 관리 |

이 경계에서 나오는 규칙:

- 설치기는 사용자 관리·모듈 카탈로그·코어 배포·백업·TLS 화면을 **만들지 않는다.** 그건 메인 GUI나 모듈의 몫이다(maingui 결정 Q-2).
- 메인 GUI는 **비밀번호를 그 기계의 브라우저에 넣지 않는다**(maingui 결정 Q-1 — 등록은 코드 하나). 설치기는 로컬 설치 프로그램이라 `account`·`token` 입력을 받지만, 이것이 메인 GUI에 같은 입력란을 만들 이유는 아니다.
- 미등록 leaf의 Gateway는 인증 모드 `none`이라 Daemon op가 전부 거절되고, 열려 있는 길은 등록 코드 하나뿐이다. 그래서 설치기가 `none`으로 끝낸 Leaf에 대해 약속할 수 있는 것은 "열린 화면에서 등록할 수 있다"가 전부다. 로컬 Daemon 로그인 같은 우회를 약속하지 않는다.
- 두 화면은 같은 낱말을 쓴다: **등록 · Tree에 붙기 · 새 Tree 만들기 · 나중에 등록**. 역할 선택(S1)의 Tree = "새 Tree 만들기", Leaf = "기존 Tree에 붙기"로 읽힌다.

### S1 역할
- **선택:** Leaf · Tree · 둘 다. 복수 선택(체크 카드). 둘 다 고르면 "Tree를 먼저 설치합니다" 안내.
- **보여 줄 것:** 역할마다 한 줄 설명, 설치되는 서비스(Leaf = daemon, Tree = master), 디스크 예상 크기.
- **막을 것:** 아무것도 안 고르면 다음 비활성.
- **제거된 선택지(노출 금지):** studio, master/daemon 단독, all-in-one, custom 조합.

### S2 연결 (Leaf가 포함될 때만)
설치기의 등록 방식은 엔진이 가진 넷이다(§4.1). 말은 maingui 시작 화면(O-1)과 맞춘다 — **"기존 Tree에 붙기"**.

| 방식 | 언제 | 입력 |
| --- | --- | --- |
| `auto` | 같은 기계에 Tree가 있거나 Tree와 함께 설치 | 없음. "이 컴퓨터의 Tree에 자동 연결"로 요약 |
| `account` | 다른 기계의 Tree에 붙는다(기본) | Tree 주소 + 관리자 이메일·암호 |
| `token` | 토큰을 받아 둔 경우 | Tree 주소 + 토큰 |
| `none` | **"나중에 등록"** | 없음. 설치 뒤 메인 GUI의 시작 화면에서 등록 코드로 붙는다(§4.1) |

- **검증:** 주소 형식, 도달성 확인 버튼. 기본값 `http://127.0.0.1:8080`을 그대로 두면 "이 주소는 이 컴퓨터 자신입니다" 경고(데스크톱에 Leaf만 설치할 때 실제로 겪은 실수).
- **비밀 입력:** 암호·토큰은 마스킹, 화면 밖 저장 금지, URL·로그·이벤트 스트림에 남기지 않는다.
- **`none`을 고르면** 그 결과를 숨기지 않는다 — "등록 전에는 이 컴퓨터의 브라우저에서 할 수 있는 일이 없습니다. 등록은 설치 뒤 열리는 화면에서 합니다."(maingui O-2와 같은 문장 의미)
- 등록 코드(`tnc_…`)를 설치기에서도 받을지는 미정이다(재설계 문서 Q-7). 시안에는 넣지 않는다.

### S3 모듈
- **범위 세 가지:** 필수만(기본) · 전부 · 직접 선택. 연결할 Tree가 없으면 "전부"를 권한다.
- **소스:** 인터넷(기본) · 로컬 폴더 · Tree 레지스트리.
- **목록 행:** 이름 · id · 버전 · 크기 · 출처 칩(`동봉 경로 io.terra.*` / `레지스트리 lab.stellaxia.*`) · 필수 뱃지 · 역할 칩(Leaf/Tree).
- **상태:** 가져올 수 있음 / 이미 있음 / 가져올 수 없음(오프라인). 오프라인이면 "코어는 설치하고 이 모듈은 나중에 채웁니다"를 명시.
- **메인 GUI 모듈**(`lab.stellaxia.node-gui`)은 필수 뱃지로 맨 위. 이 모듈이 없으면 첫 화면이 비는 것을 한 줄로 설명한다.

### S4 의존성
- WireGuard 등 외부 도구의 감지 결과(있음/없음/버전)와 **설치 계획**(실행할 명령, 관리자 권한 필요 여부).
- 항목별 승인 · 건너뛰기. 건너뛰면 어떤 기능이 꺼지는지 한 줄.

### S5 옵션
- 설치 위치, PATH 등록, gateway, fleet-host, ssh-server.
- **모든 옵션은 켜기·끄기가 같은 컨트롤**이다(수정 화면도 같은 컴포넌트). "한 번 켜면 끌 수 없는" 모양을 만들지 않는다.
- fleet-host를 켤 때 docker가 없으면 켜기 전에 경고(실제 사례: 데몬이 129번 재시작).

### S6 요약
- 받을 파일 수 · 총 크기 · 예상 시간, 설치 위치, 만들어질 서비스, **관리자 권한이 필요한 작업**, 건드릴 시스템 영역(PATH, 서비스, 방화벽, 예약 작업).
- 주 버튼 "설치 시작". 이 화면이 사용자가 동의하는 마지막 지점이다.

### S7 진행
- **단계 목록**(카탈로그 확인 → 받기 → 검증 → 배치 → 서비스 → 등록)과 현재 단계의 막대. 받기는 파일별 진행.
- **로그 창**(접힘 기본): 엔진 이벤트 스트림. 비밀은 `••••`로 마스킹된 채 온다.
- **등록 단계**(`auto`·`account`·`token`일 때)는 하위 단계로 풀어 보인다 — 메인 GUI(O-5)와 **같은 말**을 쓴다: 코드·계정 확인 → Master 응답 → Daemon 재시작 → Gateway 복귀. 3분을 넘기면 원인별 안내(서비스가 아니라 직접 띄운 Daemon 등)를 띄우고 멈춘 채로 두지 않는다.
- 취소 버튼 = 롤백 확인 대화상자.
- 승격이 필요하면 단계 사이에 "관리자 권한 확인" 카드(UAC/sudo 안내).

### S8 완료
- 결과 요약(설치된 역할 · 버전 · 모듈 수 · 대기 모듈 수), **"Terra 열기"** 주 버튼(런처 → 메인 GUI), 로그 보기, 닫기.
- 대기 모듈이 있으면 노란 칩으로 "N개 모듈은 연결 후 채워집니다".
- **다음 한 걸음**을 상황별로 한 줄만 보인다. 설치기는 여기까지만 하고 이어서는 메인 GUI가 맡는다(§4.1):

| 상황 | 완료 화면이 말하는 것 |
| --- | --- |
| Tree를 설치했다 | "첫 로그인 뒤 일상용 계정을 만드세요." 최초 관리자 자격 파일의 **경로**를 보인다(암호 값은 화면·로그에 쓰지 않고, 보기 단추를 눌러야 열린다). 로컬 Daemon이 자동 등록하면 그 파일은 사라진다는 것도 한 줄 |
| Leaf를 등록까지 마쳤다 | 어느 Tree에 속했는지, 장치 이름 |
| Leaf를 `none`으로 설치했다 | "열린 화면에서 등록 코드로 Tree에 붙으세요. 등록 전에는 이 브라우저에서 할 수 있는 일이 없고, 명령줄은 `terra daemon …`으로 쓸 수 있습니다." 복사 가능한 명령 |
| 등록이 시간 안에 안 끝났다 | S7의 등록 단계 안내(아래)와 같은 원인별 문구 |

### E1 원인 (실패 화면)
- 무엇이 실패했는가(단계) / **왜**(자식 프로세스 stderr 마지막 줄을 사람 문장으로) / 지금 상태(되돌려짐·부분 설치) / 할 수 있는 일(재시도 · 로그 복사 · 취소).
- 종료 코드는 사람 문장으로 번역: `10 = 설정 오류`, `20 = 런타임 오류`, `2 = 사용법 오류`.
- "exit status 20" 같은 원문만 보여 주는 화면은 금지.

### M0 유지관리 홈
- 현재 설치 카드: 제품 · 역할 · 버전 · 설치 위치 · 서비스 상태 · 모듈 수 · modules 릴리스 태그.
- 업데이트 가능 배지(카탈로그 비교). 작업 넷: 업데이트 · 수정 · 복구 · 제거.
- **수정**은 바꿀 수 있는 것이 있을 때만 노출(옵션 · 모듈 범위).

### M1 변경점
- 코어 `0.5.9 → 0.6.0`, 모듈 추가·갱신·삭제 목록. 번들에서 빠지는 모듈은 "제거됩니다"로 명시(설치 기록까지 지워진다).

### M2 점검 결과
- 원장과 디스크가 어긋난 파일 · 손으로 바뀐 파일을 표로. "고칠 항목" 체크. 손댄 파일을 덮어쓰려면 별도 확인.

### M3 / M4 제거
- **보존**(설정·데이터 유지, 설치물만 삭제) vs **완전삭제**(설치·데몬·마스터 데이터 전부). 완전삭제는 지울 경로를 나열하고 입력 확인.
- Leaf가 Tree에 등록돼 있으면 **등록 해제 제안**(제품 이름이 아니라 역할 기준).

## 5. 상태와 빈 화면

| 상황 | 표시 |
| --- | --- |
| 카탈로그 서명 검증 실패 | 최상위 오류. "받지 않았습니다". 재시도 / 로컬 폴더로 전환 |
| 카탈로그 만료 | "이 목록은 오래됐습니다" + 설치기 업데이트 안내 |
| 오프라인 | 코어는 로컬이면 진행 가능, 모듈은 "대기"로. **"없음"과 "못 봤음"을 구분**해서 표시한다 |
| 승격 거부 | 막다른 길 금지. 다시 요청 / 사용자 범위 설치 가능 여부 / 취소 |
| 포트 점유로 UI 서버가 못 뜸 | 콘솔에 사유와 `--port` 안내(웹 UI 이전 단계라 화면 없음) |
| 다른 설치기가 이미 실행 중 | 세션 단일화 안내 |

## 6. 시각 규칙

**maingui ver.2 "어두운 유리 HUD"를 따른다.** 원본: `StellaxiaLab/maingui` 의 `design/SKIN.md` · `design/icons.md` · `docs/design/gui-theme-v2.md`. 설치기는 별도 앱이지만 같은 제품군으로 보여야 한다.

| 쓰임 | 값 |
| --- | --- |
| 화면 바탕 | `#07090c` ~ `#0d0f13` |
| 유리 패널 | `rgba(13,15,19,.82)` + `backdrop-filter: blur(14px)`, 테두리 `1px solid rgba(255,255,255,.10)`, 모서리 14 |
| 글자 | 본문 `#ede9e1` · 보조 `#b4bac3` · 흐림 `#9aa1ab` |
| 주 버튼 | 바탕 `#ede9e1` · 글자 `#111` |
| 보통 버튼 | 바탕 `rgba(255,255,255,.04)` · 선 `.18` · 모서리 9 · 높이 34 |
| 역할 색 | Tree `#f0a63a` · Leaf `#5aa8ff` |
| 상태 색 | 정상 `#3ecf8e` · 주의 `#f5b83d` · 실패 `#ff5d5d` · 정보 `#7aa7ff` |
| 글꼴 | `Noto Sans KR` 본문 · `JetBrains Mono` id·경로·해시 · 워드마크 `TERRA` 자간 .42em |
| 아이콘 | 선 아이콘(viewBox 24, stroke 1.8, round). 이모지 금지 |

- **설치기는 네트워크 없이도 뜬다.** 글꼴·아이콘·스크립트 전부 바이너리에 임베드한다. 외부 CDN 참조 금지(보안상 CSP도 막는다).
- 대비는 WCAG AA 이상. 유리 효과 위 글자는 불투명 배경을 한 겹 깐다.
- `prefers-reduced-motion`이면 진행 애니메이션을 줄인다. 키보드만으로 전 흐름을 끝낼 수 있어야 하고 포커스 링을 숨기지 않는다.
- 창 크기는 고정 비율 하나(예: 960×640)로 시작한다. 좁은 화면(터널 접속 노트북)에서도 가로 스크롤이 없어야 한다.

## 7. 문구 원칙

- 한국어 기본, 다국어 구조는 열어 둔다(문구는 키로 분리).
- 사람이 하는 일은 동사로, 시스템이 하는 일은 결과로: "연결을 확인합니다" 아니라 "Tree에 연결할 수 있어요".
- **오류 문장은 원인 + 지금 상태 + 다음 행동** 순서. 원문(stderr)은 접힌 "자세히"에만.
- "없음"이라고 단정하기 전에 못 본 것은 아닌지 구분한다(오프라인·권한 부족 등).
- 보안 용어는 한 번 풀어 쓴다: "서명 확인됨 — Terra가 발행한 목록입니다".

## 8. 데이터 계약 (UI가 엔진에서 받는 것)

UI는 엔진과 JSON 이벤트로만 통신한다. 아래는 디자인에 필요한 필드이며 **정확한 스키마는 구현 단계에서 확정**한다.

| 화면 | 받는 데이터 | 보내는 데이터 |

| 시작 | `{installed: bool, product, roles[], version, services[], catalog: {version, signature_ok, expires_at}}` | — |

| S2 | `{local_tree_found, default_url, enroll_modes: [auto \| account \| token \| none]}` | `{mode, tree_url, email, password \| token}` (`none`·`auto`는 나머지 없음) |
| S3 | `{modules: [{id, version, size, origin, required, roles[], availability}]}` | `{scope, selected[], source}` |

| S5 | `{options: [{key, value, can_toggle, warning}]}` | `{options{}}` |
| S6 | `{downloads: {count, bytes}, admin_steps[], touches[]}` | `{confirm}` |
| S7 | 이벤트 스트림 `{step, state, progress, log_line}` | `{cancel}` |

## 9. 산출물과 완료 기준

디자인 세션이 낼 것:

1. 화면 18개(S1~S8, E1, M0~M4 + 빈·오류 상태 변형)의 정적 시안 — HTML/Figma 어느 쪽이든
2. 컴포넌트 목록(체크 카드, 모듈 행, 단계 목록, 진행 막대, 오류 카드, 확인 대화상자)과 상태 변형
3. 문구표(키 · 한국어 문구 · 사용 화면)
4. 위 §8 데이터 계약에 대한 보강 요청(빠진 필드)

완료 기준:

- 처음 쓰는 사람이 S1→S8을 **질문 7개 이내**로 끝낸다(둘 다 설치 + 자동 연결이면 더 적다)
- 모든 실패 화면이 원인 + 상태 + 다음 행동을 가진다
- 오프라인에서도 모든 화면이 렌더되고, 외부 요청이 0이다

## 10. 하지 말 것

- 새 기능을 상상해 추가하지 않는다. 엔진이 못 하는 선택지(예: 모듈 개별 버전 고르기)는 시안에 넣지 않는다 — 넣고 싶으면 §9-4로 요청한다.
- 비밀(암호·등록 코드·토큰)을 URL·제목·로그 영역에 노출하는 화면을 그리지 않는다.
- 기존 Windows 마법사의 화면 구조(페이지 5장 + 별도 진행 창)를 그대로 옮기지 않는다. 흐름은 위 §3이 정본이다.
- 위험 작업(완전삭제, 손댄 파일 덮어쓰기)에 한 번 클릭으로 닿는 경로를 만들지 않는다.
