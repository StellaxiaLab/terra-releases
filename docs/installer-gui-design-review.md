# 설치기 GUI 시안 검토 — 디자인 세션 인계

대상: `StellaxiaLab/terra-releases` 브랜치 `design/installer-gui` 커밋 `0e1adab`(18화면, `canvas.json`).
기준: GUI 디자인 브리프.
구현은 Terra 쪽 세션이 맡고, **이 문서의 항목은 디자인 세션이 시안에서 고친다.**

## 1. 결론

브리프의 흐름·용어·상태 변형은 잘 따랐다. 아래 §2~§3을 고치면 구현 인계가 가능하다. §4는 구현 세션이 시안을 받을 때 기대하는 형식이다.

잘 된 것(유지할 것): 용어 정렬(새 Tree 만들기 / 기존 Tree에 붙기), S2 등록 방식 넷과 `none` 안내, S3 필수·출처·상태 표시, S4 sudo 명령과 건너뛸 때의 영향, S5 docker 경고, S7 등록 하위 단계와 로그 마스킹, E1의 원인·상태·다음 행동, M1의 "설치 기록까지 지워집니다", M3의 확인 문구, V2의 "없음"과 "확인 못 함" 구분.

## 2. 고칠 것 (우선순위순)

| ID | 화면 | 문제 | 요청 |
| --- | --- | --- | --- |
| DR-1 | 전체 | **Linux 한 가지뿐.** 경로 `~/.local/...`, `apt-get`, `sudo`만 있다. 주된 데스크톱 대상은 Windows다 | Windows 변형을 만든다: 설치 위치(`%LOCALAPPDATA%`/`Program Files`), UAC 승인 안내(V3), 사용자 PATH 등록, 서비스·예약 작업, M3의 지워질 위치. 가능하면 한 시안에서 OS 탭/토글로 전환(S8의 Tweaks 방식) |
| DR-2 | S3, V2, 칩 | 출처 라벨 "레지스트리 · lab.stellaxia.*"가 오해를 부른다. node-gui는 Tree 레지스트리가 아니라 **modules 릴리스**에서 온다 | 라벨을 `modules 릴리스 · lab.stellaxia.*` / `동봉 · io.terra.*`로. "Tree 레지스트리"는 **받는 곳** 선택지(S3 상단)에만 남긴다 |
| DR-3 | 전체 | 키보드 포커스 표시가 없다(`:focus-visible` 0건). 모든 테두리를 `border:0!important`로 지우는 규칙이 있어 포커스·선택 윤곽도 같이 사라질 수 있다 | 포커스 링을 정의(2px 외곽선 + 오프셋, 유리 배경 위에서도 보이는 색)하고, 테두리 제거 규칙에서 포커스·선택 상태를 제외한다. 전 흐름을 Tab만으로 끝낼 수 있는지 확인 |
| DR-4 | M3 | 확인 문구가 한글 `terra 제거` — IME 상태에 따라 입력이 번거롭다 | 영문(`terra` 또는 노드 이름)으로. 붙여넣기 허용 여부도 정한다 |
| DR-5 | S6 | "건드리는 시스템 영역"이 PATH·서비스·방화벽·예약 작업을 항상 나열한다 | **실제로 건드리는 것만** 표시. 건드리지 않는 항목은 숨기거나 흐리게 하고, 선택(PATH 등)에 따라 달라지게 한다 |
| DR-6 | V3 | "다시 시도"·"내 계정으로만 설치"가 카드와 하단 버튼에 중복 | 한 곳으로. 카드는 설명, 행동은 하단 |
| DR-7 | M0 | modules 릴리스 표기가 `modules-2026.09` | 실제 태그 형식 `v2026.10.05` |
| DR-8 | S7 | 진행 중에 비활성 "다음" 버튼이 보인다 | 브리프대로 진행 중에는 취소만 둔다 |

## 3. 확인·보강 요청

| ID | 내용 |
| --- | --- |
| DR-9 | **외부 폰트 참조**(`fonts.googleapis.com`, 18/18)는 시안에서는 괜찮다. 단 구현은 woff2를 바이너리에 임베드한다(CSP로 외부를 막는다). 사용한 글꼴·굵기를 `fonts.md`에 적어 달라(Noto Sans KR 400/500/600/700, JetBrains Mono 500/600로 보이는데 확인) |
| DR-10 | **서명 실패 화면(V1)**: 키 지문 `9f2c…41ab`처럼 일부만 보이는 값은 구현이 전체를 줄 수 있다. 복사 가능한 전체 지문과 "자세히"에 인증서 기간 정보를 둘지 정해 달라 |
| DR-11 | **만료된 카탈로그**(브리프 §5 "이 목록은 오래됐습니다")와 **롤백 거부**(옛 버전 카탈로그)는 시안에 없다. V 시리즈에 추가 |
| DR-12 | **이어받기·재시도**: E1은 "다시 시도"만 있다. 받기 단계에서 일부 받은 상태(9/13)를 이어서 받는지/처음부터인지 문구를 정해 달라 |
| DR-13 | **좁은 화면**(터널 접속 노트북 ≤ 800px)에서 좌측 단계 표시줄(168px)이 접히는 방식을 정의 |
| DR-14 | **`prefers-reduced-motion`**은 12/18 화면에만 있다. 전 화면 일관되게 |
| DR-15 | **실행 첫 화면 전**: 포트·토큰 문제로 UI가 못 뜨는 경우는 콘솔 문구이므로 시안 대상이 아니다(구현이 쓴다). 제외 확인 |

## 4. 구현 세션이 시안에서 기대하는 것

1. 화면별 **상태 변형 목록**(기본/로딩/오류/빈) — 화면마다 구현할 케이스를 센다
2. **컴포넌트 목록**(체크 카드, 모듈 행, 단계 목록, 진행 막대, 오류 카드, 확인 대화상자, 칩 종류)과 변형
3. **문구표**: 키 · 한국어 · 사용 화면. 시안 안의 문구가 곧 정본이 되지 않게
4. 색·간격은 브리프 §6 토큰으로 쓰고, 새 토큰이 필요하면 추가를 명시
5. 시안 파일 구조는 지금 그대로(`design/installer-gui/*.dc.html` + `canvas.json`) 유지 — 구현이 화면 ID로 참조한다

## 5. 구현 쪽이 시안에 영향을 주는 사항

- 데이터 계약(브리프 §8)은 구현 중에 바뀔 수 있다. 바뀌면 이 문서의 §6에 기록한다.
- 시안의 모든 숫자·경로·버전은 예시이며 엔진 이벤트에서 온다.
